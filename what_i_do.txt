📌 ภาพรวม (Overview)
เป็น สคริปต์ Data Cleaning & Feature Engineering Pipeline สำหรับประมวลผลข้อมูล วางระบบการตรวจเช็กกฎทางธุรกิจ (Business Rules Check) เตรียมฟีเจอร์สำหรับ Machine Learning และทดสอบ Baseline Model สำหรับ 2 โครงการหลัก:

1.Abnormal Listing Detection — ระบบตรวจจับประกาศขายสินค้าที่ผิดปกติ ทุจริต หรือเป็นสแปม (dataset_abnormal_listing.xlsx)
2.Product Recommendation System — ระบบแนะนำสินค้าให้แก่ผู้ซื้อ (dataset_recommendation.xlsx)

🔍 สรุปการทำงานแบ่งตามส่วน (Pipeline Breakdown)
PART 1: Abnormal Listing Detection Pipeline
1.Data Concatenation & Isolation: รวมข้อมูลจาก 4 ชุด (Train, Validation, Test, UAT) เข้าด้วยกันชั่วคราวเพื่อใช้กฎทำความสะอาดเดียวกัน แล้วคงป้ายกำกับชุดข้อมูลไว้เพื่อแยกออกตอนท้าย
2.Intentional Null Handling: จำแนกค่า Null ที่ถูกตั้งใจสร้างขึ้นในสคริปต์ทดสอบ (NEGATIVE / EDGE Scenarios) ไว้ ไม่ให้เผลอลบทิ้งหรือ Impute ค่าทับผิดพลาด
3.Text Cleaning & Feature Extraction:
    ทำความสะอาดข้อความ ลบสัญลักษณ์พิเศษ/Emoji และจัดระเบียบช่องว่าง
    สกัดฟีเจอร์ Title_has_emoji และ Description_has_emoji เป็นตัวเลข (1/0)
    คำนวณความยาวข้อความ Title_length และ Description_length
4.Flag Encoding & Range Validation:
    แปลงค่า string 'Yes'/'No' ในคอลัมน์ flag (เช่น Duplicate Image, Counterfeit, Spam Behavior) ให้เป็น 1/0
    ตรวจสอบขอบเขตค่าตัวเลขตาม Data Dictionary (เช่น Seller Rating 0-5, Risk Score 0-100, Price >= 0)
    Categorical Encoding (ป้องกัน Target Leakage): ทำ One-Hot Encoding ให้กับคอลัมน์ประเภท โดยถอดคอลัมน์ป้ายกำกับ เช่น Risk Band ออกจากฟีเจอร์ขาเข้า เพื่อป้องกันปัญหา Target Leakage
5.Export & Baseline Model:
แยกข้อมูลและส่งออกเป็นไฟล์ CSV 4 ไฟล์: listing_train_clean.csv, _val_, _test_, _uat_
มีโค้ดประเมิน Baseline Model ด้วย RandomForestClassifier (ผลลัพธ์ Accuracy 94%)

PART 2: Product Recommendation System Pipeline
1.Business Rules Enforcement:
    ตรวจสอบสถานะสินค้า ต้องเป็น Active เท่านั้น (BR002–BR004)
    ลบรายการที่ Buyer_ID + Product_ID ซ้ำซ้อนกันออก (BR009)
2.Pipe-Delimited Processing: แปลประวัติการค้นหา/เข้าชมสินค้าที่คั่นด้วยเครื่องหมาย | (เช่น Search_History, Wishlist) ให้กลายเป็น Python List และนับจำนวนรายการ (_count)
3.PDPA / Privacy Scan (BR008): สแกนหาข้อมูลส่วนบุคคลหลุดรอด (เบอร์โทร, อีเมล, เลขบัตรประชาชน) ในฟิลด์ข้อความอิสระ
4.Data Integration & Feature Encoding:
    Join ตาราง Recommendation_Dataset กับ Buyer_Profile ด้วย Buyer_ID
    ทำ One-Hot Encoding ให้กับข้อมูลประเภทสินค้า ผู้ซื้อ และพฤติกรรม (Behavior_Type)
5.Export & Dual Model Evaluation:
    ส่งออกไฟล์ CSV สำหรับนำไปใช้งานต่อ: recommendation_clean.csv, cold_start_clean.csv, buyer_behavior_clean.csv, feedback_clean.csv
ประเมิน Baseline Model 2 รูปแบบ:
Binary Target (Accept vs Reject): สำหรับใช้งานจริงเชิงธุรกิจ (Accuracy 100%)
Multi-class Target (3 Classes): สำหรับวิเคราะห์การแนะนำตาม Popularity/Cold-Start
